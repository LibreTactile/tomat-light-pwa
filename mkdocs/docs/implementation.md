# **TOMAT Light PWA Implementation**

## **Overview**

The TOMAT Light system is a Progressive Web App (PWA) that provides a tactile interface with WebRTC communication capabilities. It runs natively in the browser, managing button states, providing haptic feedback via the Web Vibration API, and communicating with external clients (Navigator Extension) through peer-to-peer WebRTC connections.

## **Architecture Overview**

The system follows a peer-to-peer architecture where the PWA acts as the "Interface" and the Chrome Extension acts as the "Navigator". Firebase Firestore is used strictly as a signaling broker to establish the connection, after which data flows directly between peers.

## **Component Details**

### **1. WebRTC Communication System**

The `WebRTCManager` is the central communication hub. It handles the complexity of NAT traversal, signaling, and connection state management.

**Key Features:**

- **Role-Based Connection:** The PWA always assumes the `interface` role, while the extension assumes the `navigator` role.
- **Deterministic Identity:** Peer IDs are generated by hashing the Public IP and User Agent. This ensures that refreshing the page recovers the same identity, preventing "ghost" peers.
- **Local Network Discovery:** Peers discover each other by querying Firestore for the opposite role sharing the same Public IP.

### **2. State Management System**

The State Manager translates external state data into button behaviors. It processes JSON payloads received via the WebRTC Data Channel to update the UI and haptic patterns.

**State Hierarchy:**

1. **INACTIVE** (Gray, No Feedback)
2. **ACTIVE** (Green, Continuous Vibration)
3. **PULSATING** (Red, Rhythmic Vibration)

**Data Processing Flow:**


#### **Advanced Input Handling**

To ensure robust tactile feedback on mobile devices, the application bypasses standard "hover" events (which often fail during active touch sliding) and implements a **manual coordinate-tracking system**.

**Key Implementation Details:**

1. **Global Event Listeners**
   - Attached at `document` level to track finger movement continuously
   - `touchstart`: Captures initial contact and flags input as touch device
   - `touchmove`: Core logic for detecting entry/exit via coordinate comparison
   - `touchend`/`touchcancel`: Cleans up state and halts vibration

2. **Coordinate Detection Logic**
   ```javascript
   class VibrationHandler {
     constructor() {
       this.activeTouch = null;
       this.isTouchDevice = false;
       this.buttons = new Map();
     }
     
     updateTouchPosition(x, y) {
       // Manual hit detection against button boundaries
       for (const [button, bounds] of this.buttons) {
         const isInside = Utils.isPointInsideCircle(x, y, bounds);
         if (isInside && !button.isTouched) {
           this.triggerEnter(button);
         } else if (!isInside && button.isTouched) {
           this.triggerExit(button);
         }
       }
     }
   }
   ```

#### **Button State Management**

```javascript
function updateButtonState(buttonElement, state) {
  // Remove all state classes
  buttonElement.classList.remove('inactive', 'active', 'pulsating');
  
  // Add the appropriate state class
  switch(state) {
    case 'INACTIVE':
      buttonElement.classList.add('inactive');
      break;
    case 'ACTIVE':
      buttonElement.classList.add('active');
      break;
    case 'PULSATING':
      buttonElement.classList.add('pulsating');
      // Start pulsating animation
      break;
  }
}
```

### **4. Haptic Feedback System**

Replaces Godot's vibration system with the Web Vibration API.

**Vibration Patterns:**
```javascript
// ACTIVE: Continuous vibration
function activeVibration() {
  // Create 2-second continuous pattern: 50ms on, 50ms off
  const pattern = [];
  for (let i = 0; i < 20; i++) {
    pattern.push(50, 50);
  }
  navigator.vibrate(pattern);
}

// PULSATING: Rhythmic pulses  
function pulsatingVibration() {
  // Heartbeat pattern: 200ms on, 100ms off
  navigator.vibrate([200, 100, 200, 100, 200, 100, 200]);
}

// Stop all vibration
function stopVibration() {
  navigator.vibrate(0);
}
```

### **5. Signaling & Discovery System**

The `SignalingManager` abstracts the Firestore interactions required to bootstrap the WebRTC connection.

**Signaling Workflow:**

1. **Initialization:** The app loads and retrieves the public IP via STUN server.
2. **Registration:** The PWA writes a document to the `peers` collection with:
   ```javascript
   {
     peerId: 'hashed-ip-and-ua',
     role: 'interface',
     status: 'available',
     publicIp: '192.168.x.x',
     lastSeen: firebase.firestore.FieldValue.serverTimestamp()
   }
   ```
3. **Heartbeat:** A `setInterval` updates the `lastSeen` timestamp every 10 seconds.
4. **Handshake:** The PWA listens for documents in the `sessions` collection where `targetPeer` matches its ID, then processes offers/answers/candidates.

### **6. Sidebar Controller (Chrome Extension)**

The sidebar acts as the remote controller for the PWA.

**Interaction Logic:**

- **Connectivity**: Listens to `onConnectionStateChange`. When connected, enables the message input.
- **Messaging**: 
  - `dataChannel.send(text)`: Sends user input to the PWA.
  - `dataChannel.onmessage`: Receives data from the PWA. If it's a string, it's logged to the UI; if it's JSON, it's processed as state data.
- **Persistence**: Uses the extension background script to maintain the WebRTC session, allowing the sidebar to be closed and reopened without losing the peer connection.

## **Technical Implementation Notes**

### **PWA Features**
- **Service Worker**: For offline functionality and background syncing
- **Web App Manifest**: Enables installation to home screen
- **Secure Context**: Requires HTTPS for WebRTC and Vibration API

### **Browser Compatibility**
- **WebRTC**: Chrome 74+, Firefox 68+, Safari 13.1+
- **Vibration API**: Chrome 32+, Firefox 47+, Safari (No Support)
- **PWA Features**: Chrome 68+, Firefox 86+, Safari 16.4+

### **Performance Considerations**
- **Touch Events**: Debounced to prevent excessive vibration triggering
- **WebRTC**: Data channels optimized for small message sizes (<16KB)
- **Animation**: CSS transforms for smooth button interactions
- **Memory**: Cleanup of event listeners on page unload

## **Security & Privacy**

1. **WebRTC Security**: DTLS encryption for all peer-to-peer data
2. **Firestore Rules**: Restrictive security rules allowing only necessary operations
3. **No Data Persistence**: Button states and messages not stored persistently
4. **Local Network Only**: Discovery limited to peers sharing the same public IP

## **Deployment**

1. **Firebase Setup**: Configure Firestore with appropriate security rules
2. **Web Server**: HTTPS required for PWA installation and WebRTC
3. **Extension**: Package and deploy to Chrome Web Store
4. **Updates**: Service worker caching strategy for offline functionality
